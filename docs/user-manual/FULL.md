# NeuroSync Sovereign OS — User Manual

**What this manual is for**  
This manual explains the main screens in NeuroSync Sovereign OS from the user’s point of view. It tells you what each screen does, what you can change on it, and how to use it.

**How to read it**  
Start with the first section, “The Whole App in One Minute,” then read each dashboard in order. Each dashboard section usually has four parts:

- What this screen is
- What you can see on it
- What you can do on it
- How to use it in real life

**Two notes before you begin**

1. Some words in the app are technical. This manual explains them in plain language first, then gives the technical name when it matters.
2. Some parts may not show up until the app is set up enough. If a button or option is missing on your screen, that does not always mean it is broken. It may just not be ready yet.

## The Whole App in One Minute

NeuroSync Sovereign OS is a local computer system for managing AI work. It helps you do things like:

- ask the system to plan a job,
- approve or reject that plan,
- pick which AI service answers,
- run the job,
- store the results,
- keep memories,
- and watch what is happening in the background.

You do not need to know every piece at once. At a high level, the app works like this:

1. You describe what you want.
2. The app turns that into a plan.
3. You approve the plan.
4. The app runs it.
5. The app saves what happened and keeps useful memories.
6. You can check the results later.

The main screens are grouped by what they do. Here is the quick map:

- **System View** — the main overview and basic settings
- **Task Runner** — starts and watches work
- **Storage & Backups** — keeps data safe and saves copies
- **AI Model Settings** — chooses which AI service handles work
- **Project Planner** — writes requests and shapes plans
- **Approvals & Tools** — controls permissions and connected tools
- **Background Watcher** — notices things and suggests next steps
- **Memory** — keeps and refreshes stored information

A useful idea to remember: the app is built so that important actions usually wait for a person. The machine can prepare a lot, but it is meant to ask before it does something big.

Another useful idea: the app uses a sidebar with module names. Each name is a different screen. You switch screens by picking a module.

## Before You Start Using It

Most screens share a few things in common. Knowing these will make the rest of the manual easier.

### The top bar

At the top of the app you usually see:

- the app name and current screen name,
- a way to switch between Dashboard and Set-up,
- a simple/dev toggle,
- a theme toggle,
- the current project or context.

### Dashboard and Set-up

Many screens have two views:

- **Dashboard** — the main page for that screen. It shows the most important information.
- **Set-up** — the settings page for that screen. This is where you change choices that affect how that part works.

If a screen has both, you usually move between them with buttons near the top.

### Simple mode and developer mode

The app can show either:

- plain friendly words, or
- more technical words and details.

If you are learning, simple mode is the easier place to start. If you want to see more detail, developer mode may show extra labels and messages.

### Projects and context

Some parts of the app depend on a project or workspace. If you switch projects, some screens may change because they show information for the project you picked.

### What “status” usually means

Across the app, many things have a status. Status just means “what is happening with this right now.” Common statuses include things like:

- pending,
- running,
- completed,
- failed,
- blocked,
- approved,
- rejected.

When you see a status, think of it as a short update, not a final judgment.
