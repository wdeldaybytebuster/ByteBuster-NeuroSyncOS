# 5. Project Planner

## What this screen is

Project Planner is the part of the app where you tell it what you want and ask it to shape that idea into a plan.

In technical terms, this screen is also called ScopeLogic. From the user’s point of view, it is the place where you start a task by describing the job.

A simple way to think about it is this: Project Planner is the “what should we do?” part of the app.

It helps you:

- write a request,
- turn that request into a set of steps,
- review the steps before anything runs,
- reset the session when you want to start over.

## What you can see on it

### Dashboard page

The dashboard page is built around the request-and-plan flow.

You may see:

- a place to type what you want done,
- the plan or proposal the app creates,
- a list of steps,
- a way to clear the current session and begin again.

#### The request area

This is where you type your request. The more clearly you describe what you want, the better the plan can be.

This is not just a chat box for casual conversation. It is where you set the direction for the work.

#### The plan

After you ask, the app may build a plan. That plan is usually a list of steps. Each step usually has a job to do.

You can read the steps before anything runs. That is one of the main points of this screen. It helps you see the shape of the work before it starts.

#### Reset tools

Sometimes a plan is not what you wanted, or you want to try a different direction. Project Planner usually gives you a way to clear the current session and start again.

## What you can do on it

On Project Planner, you can:

- write a request,
- read the proposed steps,
- start a workflow when you are ready,
- clear the session and begin again.

## How it works

Project Planner works by turning a request into a structured plan.

The app reads what you asked for and tries to break it into steps that make sense. Those steps can then move through the rest of the system.

The important thing to remember is that Project Planner does not usually run the final job by itself. It helps shape the idea. The actual running and scheduling usually belong to other parts of the app.

A normal flow often looks like this:

1. You type a request.
2. The app turns it into steps.
3. You review the steps.
4. If the steps look good, the plan can move to approval.
5. If not, you can change the request or reject the plan.

That means Project Planner and the approvals screen often work together. Project Planner makes the plan. The approvals screen helps decide whether to allow it.

## How to use it in real life

Use Project Planner when:

- you have something you want the app to do,
- you want the app to turn an idea into steps,
- a plan needs editing before it goes any further,
- you want to start a new task from scratch.

A good habit is to describe the result you want, not just the topic. For example, tell the app whether you want something fast, careful, cheap, or detailed if that matters.

Another good habit is to break big requests into smaller ones if the first plan looks too broad or messy.

## Small tips

- Be specific about the result you want.
- If your request is large, try making it smaller.
- If the first plan looks wrong, that is normal. You can try again.
- Do not assume the first draft is the final one.
- If you are unsure about a plan, read the steps before approving anything.
